# 位置編碼：從 Sinusoidal 到 RoPE

自注意力讓 Transformer 得到了並行訓練的能力，但也帶來了一個結構性的盲區：**它對 token 的位置完全不敏感。** 打亂整個輸入序列，注意力的計算結果不變——因為 Q·K 的點積只取決於 token 的內容表示，與它們在序列中的先後順序無關。

但語言有嚴格的順序。「我打你」和「你打我」包含完全相同的三個 token，含義卻截然相反。RNN 透過序列計算自然地保留了位置資訊——Transformer 用並行換來了訓練速度，卻丟掉了這個隱含的序列結構。位置編碼要做的事就是把這個丟掉的序列結構補回來。

從 2017 年的固定正弦函式，到 2021 年蘇劍林提出的 RoPE，再到今天配合 NTK/YaRN 外推到 128K 上下文——位置編碼的演進是 Transformer 架構演化中最具工程智慧的線索之一。本文按時間線梳理這條路徑，目標是讓讀者理解 RoPE 的數學直覺和它為什麼能打破訓練長度的限制。

---

## 一、第一代：絕對位置編碼——告訴模型「你在第幾個」

位置編碼最樸素的想法是給每個位置分配一個唯一的向量，加到 token embedding 上，讓模型知道這個 token 在序列中的絕對位置。

### 1.1 固定正弦編碼（原始 Transformer，2017）

原始 Transformer 用固定的正弦和餘弦函式為位置 pos 的第 i 個維度生成編碼值：

```text
PE(pos, 2i)   = sin(pos / 10000^(2i/d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
```

每個維度對應不同頻率的正弦波。高頻維度（i 小）波長短，編碼區域性偏移；低頻維度（i 大）波長長，編碼全域性位置。這套方案不需要任何訓練——位置編碼完全由數學公式決定。

但這種固定編碼有兩個隱藏問題。第一，**外推效果差**：雖然數學上 pos 可以任意大，但模型只在訓練時見過的位置範圍（如 0-2047）內學會了如何利用這些編碼，超出訓練範圍後表現會顯著退化。第二，**它編碼的是絕對位置而非相對關係**——模型學到的是「第 5 個 token 有什麼編碼模式」，而不是「兩個 token 相距 5 步意味著什麼」。

### 1.2 可學習位置編碼（BERT / GPT-2 / GPT-3）

將固定函式替換為一個可學習的 Embedding 表：

```python
pos_embeddings = nn.Embedding(max_position_embeddings, hidden_size)
# 輸入是位置索引 [0, 1, 2, ..., seq_len-1]
```

模型在訓練中自行學習最優的位置表示。這解決了「固定函式不夠靈活」的問題，但付出了更大的代價：**徹底喪失了外推能力**——位置表只有 max_seq_len 行，超出即越界。GPT-3 訓練長度 2048 意味著推理長度也被鎖死在 2048。

## 二、第二代：相對位置編碼——從「絕對位置」到「位置關係」

絕對位置編碼的根本問題在於：注意力的本質是 token 之間的互動，而非 token 的獨立屬性。模型真正需要知道的不是「A 在第 5 位」，而是「A 和 B 之間相距多遠」。

這個洞察催生了第二代方案：**不修改 token 的表示，而是修改注意力計算本身。**

### 2.1 T5 的相對偏置

T5 在注意力分數上直接加一個可學習的偏置項，其值只取決於兩個 token 之間的相對距離：

```text
Attention(Q, K, V) = softmax((Q · K^T) / √d_k + bias_rel(i, j)) · V
```

其中 bias_rel(i, j) 只與 |i - j| 有關。相同距離的 token 對共享同一個偏置值；相對距離被分到固定數量的 bucket（T5 用 32 個 bucket），偏置表是與 max_len 無關的 O(1) 級固定開銷。

核心理念的變化：**位置信息不再注入 token 的表示，而注入注意力計算本身。** 影響的是「誰該關注誰」，不是「token 長什麼樣」。

### 2.2 ALiBi：連偏置表都不需要

ALiBi（Attention with Linear Biases）更激進——把可學習的偏置表替換為一個固定的線性懲罰項：

```text
Attention(Q, K, V) = softmax((Q · K^T) / √d_k - m · |i - j|) · V
```

其中 m 是每個 head 預定義的斜率（head_0: m=1/2, head_1: m=1/2², ...）。距離越遠，懲罰越大——這是一個極簡的「就近原則」。

**關鍵發現**：只用這個固定懲罰項，不加任何可訓練的位置編碼，模型就能外推到訓練時約 2-3 倍的上下文長度（經驗口徑；ALiBi 論文未給出統一倍數）。Bloom 使用了 ALiBi，實測推理長度可以達到訓練的 3 倍以上。但 ALiBi 也有局限——線性懲罰過於簡單，對複雜的長距離依賴模式表達能力不足。

## 三、RoPE：旋轉位置編碼——將位置資訊「旋入」注意力

RoPE 由蘇劍林等人在 2021 年提出，目前是 LLaMA、Qwen、DeepSeek、Mistral、Gemma 等幾乎所有當代 LLM 的位置編碼方案。它的核心思路獨樹一幟：**不改變向量的大小，只旋轉向量的方向**，且將旋轉角度與 token 位置繫結。

### 3.1 直覺：用旋轉編碼位置

想象兩個 token 的 Q 和 K 向量在空間中各有一個方向。如果這兩個向量的旋轉角度差正好等於它們的相對位置差，那麼它們的點積（cos 值）就自然攜帶了相對位置資訊——位置近則角度差小、cos 大，位置遠則角度差大、cos 小。

RoPE 正是利用了這個幾何直覺：對 Q 的第 g 對維度施加角度 pos_i × θ_g 的旋轉，對 K 施加 pos_j × θ_g 的旋轉。那麼 Q 和 K 的點積中，旋轉角之差 (pos_i - pos_j) × θ_g 會自然出現。

### 3.2 數學定義

將 d 維的 Q 或 K 向量按相鄰維度兩兩分組 ((x₀, x₁), (x₂, x₃), ...)，對每一組施加一個二維旋轉矩陣：

```text
對於第 g 組 (x_2g, x_2g+1)：
  旋轉角 θ_g = 1 / (base^(2g/d))    其中 base = 10000

[f(x_2g, pos)]   [cos(pos·θ_g)  -sin(pos·θ_g)]   [x_2g]
[             ] = [                            ] × [    ]
[f(x_2g+1, pos)]  [sin(pos·θ_g)   cos(pos·θ_g)]   [x_2g+1]
```

用複數形式表達更簡潔——將每組視為一個複數，乘以 e^(i·pos·θ_g)：

```text
(x_2g + i·x_2g+1) · e^(i·pos·θ_g)
```

不同維度組的旋轉頻率不同（θ_g 隨 g 增大而減小），低頻組感知遠端位置關係，高頻組感知近程區域性變化。

### 3.3 為什麼 RoPE 編碼的是相對位置

RoPE 的數學優雅之處在於，旋轉後 Q 和 K 的點積只包含相對位置項：

```text
RoPE(Q_pos_i, pos_i) · RoPE(K_pos_j, pos_j)^T
= (Q_i · e^(i·pos_i·θ)) · (K_j · e^(i·pos_j·θ))^T
= (Q_i · K_j^T) · e^(i·(pos_i - pos_j)·θ)     ← 只與相對位置有關!
```

絕對位置在旋轉過程中自動消去，剩餘項 e^(i·(pos_i-pos_j)·θ) 純編碼相對距離。這意味著 RoPE 兼具了絕對位置編碼的簡潔（直接對 Q/K 做變換，無需修改注意力公式）和相對位置編碼的表達力（自然編碼 token 間距離）。

### 3.4 外推：突破訓練長度上限

RoPE 能支援比訓練時長得多的上下文，關鍵在於旋轉頻率是可調的。透過調整 base 值或對不同頻率組做差異化縮放，配合少量繼續訓練或微調，可以將上下文視窗從 4K 擴展到 32K-128K——Llama 3.1 用多階段繼續預訓練擴到 128K，YaRN 論文則只用約 400 步微調。

| 方法          | 原理                                 | 效果                                   |
| ------------- | ------------------------------------ | -------------------------------------- |
| 直接外推      | 不做任何處理                         | 訓練 4K → 推理 8K，perplexity 急劇上升 |
| 線性插值（PI）| 縮放位置索引，θ 不變                 | 4K → 32K，perplexity 基本持平          |
| NTK-aware     | 改變 base（見下方程式碼），高頻幾乎不動、低頻壓縮 | 4K → 32K，微調量極小        |
| YaRN          | 高頻保持、低頻壓縮，分頻段差異化處理 | 4K → 128K，多數開源模型的首選          |
| Dynamic NTK   | 根據當前實際序列長度動態調整縮放因子 | 靈活，無需預設目標長度                 |

```python
# NTK-aware 縮放的簡化實現
def apply_ntk_scaling(base, scale, dim):
    """對 RoPE 的 base 做縮放，使高頻維度衰減更緩慢"""
    return base * (scale ** (dim / (dim - 2)))
```

### 3.5 各方案權衡對比

| 方案          | 編碼方式           | 相對位置                 | 外推能力                  | 代表模型                       |
| ------------- | ------------------ | ------------------------ | ------------------------- | ------------------------------ |
| Sinusoidal    | 加到輸入端         | 間接（透過三角函式性質） | 弱                        | Transformer (2017)             |
| Learned       | 加到輸入端         | 無                       | 無（硬上限）              | BERT, GPT-2/3                  |
| Relative Bias | 加偏置到注意力分數 | 直接                     | 中等                      | T5                             |
| ALiBi         | 固定線性懲罰       | 直接                     | 強，但表達力有限          | Bloom                          |
| **RoPE**      | **旋轉 Q/K 向量**  | **直接且精確**           | **最強（配合 NTK/YaRN）** | LLaMA, Qwen, DeepSeek, Mistral |

RoPE 的成功不在於它比之前的方案更復雜——恰恰相反，它用最少的改動（只修改 Q 和 K 的計算，不需要改注意力公式、不需要額外參數）做到了最好的效果，因此成為行業標配。
