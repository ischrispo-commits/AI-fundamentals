# Scaling Laws——參數、資料、算力的三角博弈

2018 年 GPT-1 只有 117M 參數，2024 年 DeepSeek-V3 膨脹到 671B——六年翻了 5700 倍。這個膨脹不是拍腦袋的結果。每一代模型的參數規模、訓練資料量和 GPU 預算，背後都有一套經驗規律在指導決策。

這套規律就是 Scaling Laws（縮放定律）——模型性能（通常以驗證集 loss 衡量）隨參數規模 N、訓練資料量 D 和計算量 C 變化的冪律關係。它回答了一個根本問題：**給定一個算力預算，怎麼分配參數和資料才能得到最好的模型？** 答案在 2020 到 2024 年間經歷了三次重大修正，而這三次修正直接塑造了 GPT-3、Chinchilla、LLaMA 和 DeepSeek-V3 等里程碑模型的設計決策。

---

## 一、問題：算力有限時，該堆參數還是堆資料？

訓練 LLM 的算力預算 C 近似為：

```text
C ≈ 6 · N · D
```

其中 N 是參數量，D 是訓練 token 數。給定一個固定的 C，你可以選擇「大模型 + 少資料」或「小模型 + 多資料」——哪個更好？

對這個問題的不同回答，構成了三代 Scaling Laws 的分水嶺。

---

## 二、第一代：Kaplan 定律——參數優先（OpenAI, 2020）

OpenAI 的 Kaplan 等人首次系統化地研究了 loss 與 N、D、C 的定量關係，擬合出經典的冪律公式：

```text
L(N) = (N_c / N)^α_N      其中 α_N ≈ 0.076
L(D) = (D_c / D)^α_D      其中 α_D ≈ 0.095
L(C) = (C_c / C)^α_C      其中 α_C ≈ 0.050
```

核心結論是：**模型越大，在同等算力下越「資料高效」**——以 loss 下降速度衡量，增大參數量比增大資料量回報更高。這個結論直接驅動了 2020-2021 年的參數軍備競賽：GPT-3 (175B)、Gopher (280B)、MT-NLG (530B)——參數猛漲，但訓練資料量增長有限。GPT-3 的 175B 參數只配了約 300B tokens，token/param 比僅為 1.7。

Kaplan 的洞見在當時是革命性的，但他的實驗設計有一個後來被發現的盲區：**學習率排程策略不統一**。不同規模的模型使用了不同的學習率 schedule，導致小模型可能未被充分訓練，從而在資料中呈現「大模型更高效」的假象。

---

## 三、第二代：Chinchilla 定律——資料與參數同比例增長（DeepMind, 2022）

DeepMind 的 Hoffmann 等人修正了 Kaplan 的實驗缺陷——所有模型統一使用 cosine schedule 並訓練到充分收斂——得出了截然相反的結論：

```text
計算最優時：N_opt ∝ C^0.50，D_opt ∝ C^0.50
```

**參數量和資料量應該同比例增長。** 換算為工程經驗法則：每個參數配約 20 個訓練 token。

```text
由 C ≈ 6·N·D 與 D ≈ 20·N 聯立可得：
N_opt ≈ sqrt(C/120)
D_opt ≈ 20 · N_opt ≈ sqrt(10·C/3)
```

他們用算力相等的一個對照實驗戲劇性地證明了這一點：70B 的 Chinchilla（配 1.4T tokens）在几乎所有 Benchmark 上戰勝了 280B 的 Gopher（配 300B tokens）。算力一樣，但 Chinchilla 小 4 倍、資料多 4.7 倍——反而更強。

**行業影響**：2023 年以後幾乎所有開源模型都走了 Chinchilla 路線。LLaMA 1 (65B/1.4T)、LLaMA 2 (70B/2T) 的 token/param 比分別達到 21.5 和 28.6——遠超 GPT-3 的 1.7。

| 模型              | 參數量 | 訓練資料 | token/param 比 |
| ----------------- | ------ | -------- | -------------- |
| GPT-3 (2020)      | 175B   | ~300B    | 1.7            |
| Chinchilla (2022) | 70B    | 1.4T     | 20             |
| LLaMA 1 (2023)    | 65B    | 1.4T     | 21.5           |
| LLaMA 2 (2023)    | 70B    | 2T       | 28.6           |
| LLaMA 3 (2024)    | 405B   | 15T+     | 37+            |

注意 2024 年的模型已突破 20:1 的比例——說明 Chinchilla 描述的是「計算最優」而非「資料上限」，更多資料仍在持續帶來收益。

---

## 四、第三代：MoE——打破 N = N_active 的等式

混合專家模型（MoE）引入了一個新的自由度：總參數量 N_total 與每次前向激活的參數 N_active 不再相等。DeepSeek-V3 有 671B 總參數，但每次僅激活 37B——訓練和推理的成本接近 37B 模型，而能力遠超。

這給 Scaling Laws 增加了兩個新維度：

| 變數            | 含義                   | 對 Scaling 的影響              |
| --------------- | ---------------------- | ------------------------------ |
| E（專家總數）   | 模型的總容量池         | E ↑ → 知識容量 ↑，成本近似不變 |
| K（激活專家數） | 每次前向參與計算的專家 | K ↑ → 計算量 ↑，路由複雜度 ↑   |

關鍵趨勢：**MoE 的 Scaling 曲線斜率比 Dense 模型更陡**——同等算力增長，MoE 的 loss 下降更快。但存在一個最優的 K/E 比例——激活太多專家容易引發路由崩塌（token 全湧向少數專家，其餘專家閒置）。

## 五、邊界：經典 Scaling Laws 覆蓋不到的地方

### 5.1 資料品質

經典 Scaling Laws 假設資料 i.i.d.——所有 token 價值相等。實際遠非如此。多項研究給出量級相近的估計：1 個高品質 token 的效果約等於 3-5 個隨機網頁 token（經驗口徑，各研究因「品質」定義不同，倍數不一）。Phi 系列模型用精挑細選的合成資料，在小參數量上獲得遠超其規模的專項能力——這說明資料品質是 Scaling 公式中缺失的一個獨立維度。

### 5.2 資料牆

Chinchilla 定律預言 10T 參數模型需要 ~200T tokens。但網際網路高品質文字的總量估計僅 100T-300T token（2024 年前後的公開估計口徑）。這意味著資料牆將在下一兩個數量級內成為真的約束——必須依靠合成資料、多模態資料或新的架構突破。

### 5.3 推理時間 Scaling

OpenAI o1/o3 和 DeepSeek-R1 開闢了 Scaling 的第三條軸：**不 Scale 訓練，Scale 推理**。透過在推理階段投入額外的計算（長 Chain-of-Thought），模型可以用時間換品質。這條軸不受參數和資料規模的限制，是當前最活躍的前沿方向。

## 六、對工程實踐的意義

| 場景       | 關鍵原則                                                   |
| ---------- | ---------------------------------------------------------- |
| 預訓練     | 確保 token/param > 20；預算有限時優先保資料量而非參數量    |
| Fine-tune  | Scaling Laws 不完全適用——小資料 + 高品質的效果遠超公式預測 |
| 選型       | 同等參數下，訓練 token 數更多的模型通常更強                |
| 判斷天花板 | 看訓練 loss 曲線——如果斜率還在下降，繼續堆算力就還有收益   |
