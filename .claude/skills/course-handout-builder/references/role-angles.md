# 四種職缺口徑的寫法（第 5 節）

同一個機制講四次，差的是**受眾在意什麼、能聽懂什麼詞、聽完要做什麼決定**。寫的時候先想「這個人聽完會做什麼」，再決定說什麼。

## 30 秒・CxO 版（CEO／CFO／VP）

- 在意：錢、風險、時間、競爭。聽不懂也不想聽：warp、SM、bank、NCCL、PagedAttention。
- 結構：結論（一句）→ 量級（一個數字，帶比較對象）→ 對決策的意義（一句）。
- 禁詞檢查：若出現任何只有工程師懂的名詞，重寫。可以用比喻，但比喻要能被下一層追問承接（「32 個工人一條指令」可以接到 SIMT；「高速公路」接不到任何機制就不要用）。
- 範例（HBM）：「推理服務能同時服務多少人、能處理多長的文件，是由顯存容量與頻寬決定的，不是由算力決定。H200 的顯存是 H100 的 1.8 倍、頻寬 1.4 倍，所以同樣的服務用更少的卡。這是為什麼同一代晶片我們建議多付這個差價。」

## 3 分鐘・工程師版

- 在意：機制對不對、數字從哪來、邊界條件。會追問「為什麼」兩層。
- 結構：機制（怎麼運作）→ 數字（至少兩個，帶口徑）→ 邊界（什麼情況下不成立）→ 來源。
- 必須出現：至少一個公式或一條命令、至少一個「口徑」字眼（單向／雙向、dense／sparsity）。
- 範例（HBM）：「HBM 用位寬換頻率：每堆疊 1024-bit、1.2～3.2 GHz，A100 五堆疊 5120-bit，5 × 1024 × 1.593 GHz × 2 ÷ 8 = 2039 GB/s；GDDR7 是 32-bit 介面拉到 28 GHz，RTX 5090 1.79 TB/s 看起來接近，但每 bit 功耗約兩倍、容量上不去。邊界：若工作負載是 compute-bound（大 batch 的 prefill），頻寬差距就不是主要因子。來源：`01_hbm_evolution.md:21-56`。」

## TAM・排障問法

- 在意：客戶的現象 → 最快縮小範圍 → 不要讓客戶覺得被怪罪 → 給下一步與時程。
- 結構：客戶原話 → 我先問的三個問題（每個問題背後要排除什麼）→ 最可能原因與怎麼驗證（命令或指標）→ 怎麼說（先確認目標再給選項）。
- 必須出現：至少一條命令或一個指標名（`nvidia-smi topo -m`、DCGM 欄位、NCCL 環境變數）。
- 範例（HBM）：客戶說「我們換了大顯存的卡，吞吐沒變」。先問：工作負載是 prefill 為主還是 decode 為主？batch 與上下文長度有沒有跟著調？KV cache 有沒有真的用到新增的顯存（看 vLLM 的 `gpu_memory_utilization` 與 KV block 使用率）？最可能原因：引擎配置沒改，顯存多了但 batch 沒放大。說法：「卡沒問題，是設定還停在舊卡的保守值，我們一起調兩個參數再量一次。」

## Evangelist・Demo 點

- 在意：觀眾要「自己看見」，不是被告知；現場會壞，要有備案。
- 結構：讓觀眾先猜 → 跑一個命令或展示一張輸出 → 揭曉 → 一句話把「看見的」接回機制 → 失敗備案（預錄輸出、截圖、換一個等價的小實驗）。
- 必須出現：一個具體的命令、工具或視覺化（`nvbandwidth`、`nvidia-smi -q -d MEMORY`、一張 repo 的圖），以及備案。
- 範例（HBM）：「我先讓大家猜：這張 RTX 5090 和 A100 的顯存頻寬差幾倍？多數人會猜 3～5 倍。然後跑 `03_hbm_bandwidth_test` 的腳本，兩列數字出來只差 12%。這時候我再問：那為什麼資料中心不用 GDDR？帶出容量、功耗與 NVLink 的差別。備案：預錄的輸出截圖。」

## 面試官版（週五的口說受眾）

- 在意：你有沒有真的懂，還是背的；被追問會不會垮；誠實度。
- 結構：先給結論 → 給機制 → 主動說出一個邊界或你不確定的點 → 停下來等追問。
- 必須出現：「我不確定的是…，我會去查…」至少一次。這不是示弱，面試官最怕的是硬講。
