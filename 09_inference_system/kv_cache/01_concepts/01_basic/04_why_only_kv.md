# KV Cache 為什麼叫 KV Cache？——Q 去哪了

每個剛接觸 KV Cache 的人都會問這個問題：既然 K 和 V 可以快取，那 Q 呢？Prefill 時明明也算出了所有 token 的 Q，為什麼不一起存起來、Decode 時複用？

答案藏在一個簡單的類比裡——以及因果注意力的數學約束中。

## 一、檢索類比：Q 是問題，K/V 是答案庫

想象你在圖書館查資料。你走進來，翻了一遍目錄卡片和書架上的摘要，問了一個問題，得到了答案。然後你接著問第二個問題。

第二個問題不需要回憶第一個問題是什麼——那個問題已經完成了使命。但它需要**同一套目錄卡片**和**同一批書架摘要**。越問越多，卡片越摞越厚，但每次只有最新的問題在查它們。

這就是 Q、K、V 在注意力中扮演的角色：

| 角色          | 含義                                                    | 生命周期                       |
| ------------- | ------------------------------------------------------- | ------------------------------ |
| **Q (Query)** | 當前 token 提出的「問題」——"我該關注哪些之前的 token？" | 一次性：提出並得到答案後即廢棄 |
| **K (Key)**   | 每個 token 提供的「索引標籤」——"我包含哪些信息？"       | 持久：後續每個 token 都要檢索  |
| **V (Value)** | 每個 token 提供的內容摘要——"關注我的話，我貢獻什麼？"   | 持久：後續每個 token 都要讀取  |

Prefill 階段，prompt 的每個 token 都產生自己的 Q、K、V。Q 被用來查詢當時存在的所有 token——然后它就完成了使命。進入 Decode 階段後，每個新 token 的 Q 只查詢**更早的** token（因果掩碼保證），而不會去查詢過去的 Q。

```text
Decode Step t:

  Q_t 需要查詢: K_1, K_2, ..., K_t       ← 所有 Key（含自己）
  Q_t 需要讀取: V_1, V_2, ..., V_t       ← 所有 Value（含自己）
  Q_t 不需要:   Q_1, Q_2, ..., Q_{t-1}   ← 過去的 Query 對當前 token 無意義
```

## 二、因果掩碼決定了 Q 的一次性

Decoder 的 causal mask 只允許每個 token 關注自己及之前的 token。這意味著：

- token t 的 Q_t 查詢 `[1, t]` 範圍
- token t+1 的 `Q_{t+1}` 查詢 `[1, t+1]` 範圍
- **token t+1 永遠不需要用 Q_t 去查任何東西**

Q 是單次使用的：提出、得到答案、丟棄。K 和 V 是被反覆使用的：每生成一個新 token，在標準 full causal attention 下所有历史的 K 和 V 都要被讀一次。這就是 Q 不該被快取的根本原因——**快取一種不會被再次使用的東西，純粹浪費顯存。**

## 三、如果硬要快取 Q 會怎樣？

以 LLaMA-2 70B（GQA, 8 KV heads, 64 Q heads）在 seq_len=4096 時為例：

| 快取項            | 計算                                               | 大小         |
| ----------------- | -------------------------------------------------- | ------------ |
| K                 | 80 層 × 8 heads × 128 dim × 4096 tokens × 2 bytes  | ~0.63 GB     |
| V                 | 同上                                               | ~0.63 GB     |
| **KV Cache 合計** |                                                    | **~1.25 GB** |
| Q（如果快取）     | 80 層 × 64 heads × 128 dim × 4096 tokens × 2 bytes | **~5 GB**    |

快取 Q 需要額外 5 GB——但這 5 GB 的資料**永遠不會被再次訪問**。在顯存本就緊張的推理場景中，沒有比這更純粹的浪費了。

## 四、總結

歸納全文：**Q 是「問題」，每次都是新的；K/V 是「答案庫」，越積越多。快取前者無意義，快取後者是 KV Cache 的全部價值。**
