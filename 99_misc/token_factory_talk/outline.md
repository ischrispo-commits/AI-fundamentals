## 二、開場（4 分钟，3 頁）

**目標**：讓全場在 60 秒內意識到"AI 的定價體系正在發生工業革命級的變化"，並亮出封面三問的"問題底色"。

**封面三問的引入（30–40 秒，封面頁）**：

> 今年 3 月，黃仁勳在 GTC 大會上說了一句："資料中心不再是一台計算機，它是一個工廠——給工廠注入能量，產出的產品叫 Token。"今天我想用大約 40 分钟，把這個"工廠"講透。全程只回答三個問題：**Token Factory 是不是一個好生意？怎麼才能賺錢？AI Infra 有哪些事情要做？**

**敘事草稿**：

> 先看兩個數字。第一個：2023 年 3 月，GPT-4 的定價是每百萬 token 輸出 60 美元；2026 年 8 月，Qwen3.8-Flash 的同口徑價格是 3 元人民幣（約 43 美分）——單價三年跌了 140 倍。給個體積錨：100 萬 token 大約是一部 75 萬字小說的體量。上面報的都是**輸出價**——讓模型"寫"出這麼多字，三年前要 400 多塊人民幣，現在 3 塊錢。這就是 140 倍的實感。而模型還越來越聰明：一次就做對、token 用得越來越少——真實場景的花費，降得比單價還要狠【素材 08 §1】。
>
> 第二個數字：2024 年初，中國每天消耗 1000 億個 token；2026 年 3 月，140 萬億——兩年，漲了約 1400 倍。這是**國家資料局今年 3 月釋出的官方數字**【素材 05 §1.3】。給個直覺：這相當於**每天寫 1.37 億本《紅樓夢》**（每本 73 萬字），攤到 14 億人頭上，每人每天約 10 萬 token、50 篇千字文【素材 07 注】。
>
> 價格往下、用量往上，這兩個方向放在一起，像極了 140 多年前的電力革命：1882 年，愛迪生的珍珠街電站送出的第一度電，定價 24 美分——按通脹折算，相當於今天的 8 美元一度；而今天，美國一度電只要 20 美分左右。實際電價降了幾十倍，電力產業的總產值卻比蒸汽時代大了幾個數量級。工業時代用"度"度量電，數字時代用 GB 度量流量，智慧時代用 token 度量智能——**Token 就是 AI 的"度"**。

**有用性前提（頁面 01，1 分钟——先回答"有沒有用"，再亮兩個數字）**：模型能力足夠強、種類足夠豐富——"有沒有用"已經回答完了。頁面四個事實【素材 08 §1/§2/§5】：

1. 規模：每月最大開源釋出 754B–2.78T 參數；小米、螞蟻、美團相繼跨過 1T 線（美國同期 5/7 個月低於 130B）
2. 授權：**700B–1.65T 大模型以最寬鬆的 MIT 協議開源**；中國 178 個超 20B 開源釋出中，59% 采用 Apache 2.0、22% 采用 MIT
3. 生態：HF Hub 上託管 296 萬個模型；Qwen 衍生模型共 151,448 個，是 Meta 的 2.6 倍、Llama 系的 4.7 倍，每天新增約 200 個；參數橫跨 27B 至 2.4T
4. 實證：前沿閉源模型拒絕分析的攻擊程式碼，由量化開源 GLM-5.2 完成——開源連"閉源不敢幹的活"都能干

落點：**"有沒有用"不再是問題，問題是"怎麼用"——接下來的故事：token 越來越便宜，用量越來越大。**（轉場句不變，銜接"什麼叫 Token 工廠"）

**轉場句**："在回答'成本為什麼能革命'之前，先回答一個更基本的問題：什麼叫 Token 工廠？它和我們熟悉的資料中心有什麼不同？"

## 三、第一部分：什麼是 Token 工廠（7 分钟，4 頁：03–06）

**目標**：建立"從賣算力到賣智慧"的產業認知；給觀眾三把分類尺子；用"賣時間 vs 賣產出"把財務模型的引入架好。

### 2.1 黃仁勳的三步敘事 + 一張圖（頁面 03，1.5 分钟）

- 2022 提出"AI 工廠"：資料進、智能出；2025 升級："注入能量，產出 Token"；2026 GTC 宣布"推理經濟"，新 KPI = Tokens/Watt（每瓦 token 產出），目標"Token 之王"【素材 02 §1】
- 頁面的"注入"要素三件：**資本 / GPU、電力、資料 / 算法**——工廠的輸入；標準化產出只有一樣：**Token**
- 關鍵畫面：老黃的"一張圖"——橫軸 token 速率（聰明程度），縱軸每瓦吞吐（產能）；模型越聰明，速率越低，但 token 越值錢【素材 02 §2】
- 頁面落點條：**新 KPI = Tokens/Watt——每瓦 token 產出，決定工廠成本**（全篇的"主度量衡"，后面 05/10/16 頁反覆回扣）
- 觀眾 takeaway：**Token 不是同質商品，是分層定價的**

### 2.2 Token 為什麼能成為"貨幣"（頁面 04，1.5 分钟）

## 四、第二部分：財務模型（6 分钟，3 頁：07–09）

**目標**：三頁講完"賬怎麼算 → 產能邊界 → 市場現狀"，建立成本結構直覺，把懸念拋給第三部分。不再代入民間算例的具體金額——頁面上只放**公式結構、成本構成、市場真實財報**三類可驗證事實【素材 01/03 的 Excel 測算僅作方法參考，不入頁面、不口播具體數字】。

### 3.1 賬怎麼算：收入公式 + 成本構成（頁面 07，2 分钟）

- **收入側（頁面公式）**：
  ```text
  年收入 = 年產出（Tokens） × 單價（元/每百萬 tokens）
  年產出 = 卡數 × 單卡吞吐 × 時間 × 利用率
  ```
  講解口徑：四個乘數 = 買多少卡（資本）× 每張卡多快（技術）× 跑多久（運營）× 賣多少錢（市場）——**卡數和時間是錢能解決的，吞吐和單價是本事**
- **成本側（頁面構成條，128 節點 H20 叢集，TokenFactory 白皮書口徑）**：折舊 60% / 電費 8% / 網路 10% / 人力頻寬 10% / 軟體 10%【素材 07】——注意刻度：**折舊是大頭，電費是個零頭**（頁面原句，反直覺①）
- **頁面底部結論條（本頁靈魂，停 2 秒再念）**：這門生意的命脈只有兩個數：**① 提升單卡吞吐和利用率；② 提升 Token 單價（頁面畫了 ☹️——因為單價最不好提，價格戰里人人想砍它）**——① 是第三部分的技術革命，② 是第四部分的商業出路
- **口徑備料（口播 20 秒，防現場追問）**：為什麼"電費是大頭"的說法滿天飛？——兩種口徑都對：折舊期內的新叢集，折舊是大頭；折舊攤完的老叢集，電費才顯形。類比：問"買房月供佔收入多少"——剛買房的人說房貸是大頭，住了 20 年的人說水電物業是大頭，折舊期不同、口徑就不同。問一句"這房子買了幾年"，口徑就通了【素材 03 §5】；"電費攤不薄、折舊可攤薄"的推論放在頁面 16 能量維呼應
- **"利用率"歧義辨析（30 秒口播，防現場追問）**：行業裡"利用率"有兩種含義——① 裝置利用率（併發度高不高、算力滿不滿，由 batch 驅動）② 時間佔用率（一天多少小時有活幹，由需求驅動）。頁面 07 公式里"時間 × 利用率"是**時間口徑**；"單卡吞吐"已隱含裝置口徑——兩個參數正交：一個管"有沒有活"，一個管"有活時多快"
- 觀眾 takeaway：**降本的主戰場是"把折舊攤薄"（吞吐 × 利用率），不是省電**

### 3.2 產能與承諾：一天最多賣多少 token（頁面 08，1.5 分钟）

- **Goodput（合規吞吐）**：只有「成功 且 體驗達標」的請求產出的 token 才有人付錢——原始吞吐是假產能（頁面原句：不顧體驗硬灌負載，刷出的是流失中的使用者）；**可售賣產能 = 品質承諾剛被守住的極限工作點（λ_slo_max）**【素材 10】
- **承諾表（頁面表格，5 個指標全部對應"使用者體感"）**：

  | 使用者體感 | 指標 | 承諾量級（示例，按業務調整） |
  | --- | --- | --- |
  | 點下傳送後多久開始出字 | TTFT（首字延遲） | 按請求長度分檔承諾（排隊已含在內） |
  | 打字機流順不順滑 | ITL（字間隔） | P99 < 100ms |
  | 出字速度 | TPOT | 跟蹤項，不參與合規判定 |
  | 服務能不能用 | 成功率 | ≥ 99.95% |
  | 整體兌現度 | 達標率（Attainment） | ≥ 99%，逐檔分別承諾 |

- **生產實測口徑（頁面腳註，口播一句）**：input 處理量中快取命中的部分近乎免費——prefix 快取命中後 prefill 不用重算（量級見素材 10：生產實測命中 ~96%，口播說"絕大部分"即可）
- **延伸備料（不進頁面）**：λ_slo_max 的工程讀取與三階段壓測——① 粗掃：到達率幾何遞增（×2：0.5 → 1 → 2 → 4 → 8），每檔判定 PASS/FAIL（四項：TTFT P99 / ITL P99 / 請求延遲 P99 / 成功率）② 二分：在最後一個 PASS 與第一個 FAIL 之間逼近 ③ 長穩：臨界檔跑 30–60 分鐘無退化——**對外承諾必須是長穩驗證過的檔位**；工具 AIPerf（一條命令拿全套 P99 指標）——完整方法見對外文件《Token 工廠的產能怎麼算？》cluster-capacity-measurement.md，供 Q&A 引用；**每個產能數字必須繫結模型宣告**（模型 + 配置 + 拓撲，同模型才可比），通訊稅詳見頁面 15【素材 11】
- 觀眾 takeaway：**對外賣的是承諾——"你的每個請求都快而穩"；對內考核一個數字——每張卡每天產出多少合格 token。兩數必須一起報**（只有前者是賠本買賣，只有后者是自欺欺人）

### 3.3 市場現實：價格戰打到現在，真實玩家還在虧（頁面 09，2 分钟——本部分懸念最高點）

- **① 市場價（官方目錄價）**：輸入 1 元 / 輸出 3 元（每百萬 token，Qwen3.8-Flash）——注意輸入/輸出分開計價；同日雙發的 GLM-5.3-Flash 輸出 2.8 元，更低【素材 09】

## 五、第三部分：成本革命——在計算/儲存/通訊三維上的稀疏化（13 分钟，9 頁：10–18，全篇技術核心）

**目標**：給出統一物理框架——token 的成本 = 計算 + 儲存 + 通信，全部以能量計價；技術革命 = 在三維上做稀疏化；而能量不可稀疏化 → 產業終局是"每瓦 token"的競賽。非技術觀眾帶走直覺，技術觀眾帶走框架。

> 講解策略：每一維 = 一個壓力 + 一個對策 + 一組數字，不展開機制細節。三個壓力（參數越來越多 / 上下文越來越長 / 模型大到必須拆卡）與三維一一對應，結構天然自洽。

### 4.1 推理的本質與物理框架：一次生成在幹什麼（頁面 10，1.5 分钟）

- **兩張畫面（先給骨架，後講最佳化——後面每個技術點觀眾都能對號入座"它在省什麼"）**：
  - 讀題（prefill）：把整個提問一次性讀完、算完一遍，產出的"理解"存進顯存——這份存檔叫 **KV Cache，隨長度線性增長**
  - 逐字（decode）：每生成一個字，都要把全部存檔和全部權重**重新讀一遍，基於它們為下一個字做一次新計算**——每步都是一次"讀 + 算"（這正是 KV Cache 的意義：避免每步全量重算，只算增量）
- **頁面三維圖（對應三個成本壓力）**：
  - 參數越來越多 → **算**：能不算的不算
  - 上下文越來越長 → **存**：能不存的不存
  - 模型大到拆卡 → **傳**：能不傳的不傳
- 頁面底部能量條：三維都能"少做"，最終都以**能量**計價——**Tokens/W 是把三維壓縮成一維的工廠 KPI**（回扣頁面 03 的新 KPI）
- 橋接句：**成本不是一個數，是一個隨卡型、代際、最佳化水平移動的區間**——技術革命正在把整個區間往下壓
- 觀眾 takeaway：**先有推理的骨架，再看最佳化——每個技術點都是對號入座：省算、省存，還是省傳**

### 4.2 推理最佳化技術地圖：每一類都在"少做"（頁面 11，1 分钟）

- **全景頁**：把後續逐維技術先擺上桌——觀眾對號入座，知道每類技術在省什麼
- 四組（頁面四象限：對應三維 + 引擎層）：
  - **省算**（模型架構）：MoE 稀疏激活（每 token 只喚醒 3%"腦細胞"）· DSA 稀疏注意力（只讀值得讀的）· Engram 條件記憶（查表替代理解）· **MTP**（一次前向多想几步）
  - **省存**（記憶壓縮）：MLA（KV 壓進潛空間，省 93%）· 4-bit 量化（權重讀取量減 3/4）· PagedAttention（顯存按格出租）· 字首快取（命中即免 prefill 重算）· KV Offloading（HBM 放不下，分層放記憶體/盤）
  - **省傳**（拓撲與分離）：專家本地化（把專家放回常客身邊）· PD 分離（讀題吃算力、生成吃頻寬，拆開跑互不拖累，KV 跟着搬）· 拓撲感知排程（通訊路由避開慢鏈路）
  - **省時**（引擎排程）：連續批處理（利用率 30% → 80%）· 投機解碼（小模型打草稿、大模型驗證）· 動態批處理（閒時湊單、忙時拆單）
- 觀眾 takeaway：**沒有一招鮮——每代技術各壓一維，合起來才是"單價跌 140 倍"的原因**（深度原始碼拆解見本倉庫 `09_inference_system/`：vllm · sglang · model_optimization · prefill_decode；MTP 彩蛋若有技術觀眾追問，見 `model_optimization/mtp-multi-token-prediction.md`——訓練時學會"一次想好几步"，V4-Flash 實測輸出提速近 3 倍）

### 4.3 計算維：參數越來越多怎麼辦 → MoE + DSA + Engram（頁面 12，1.5 分钟）

- 壓力：模型從 7B → 671B → 1.6 萬億參數；若每個 token 都過全部參數，成本線性爆炸
- **MoE（參數稀疏）**：頁面大字 **3.06%**——V4-Pro 1.6 萬億參數只激活 490 億【素材 04 §0.1】；術語類比（頁面原句）：**專家會診：1600 位醫生，每次只叫醒 49 位**
- **DSA（注意力稀疏）**：只讓值得的 token 參與注意力——128K 上下文只選 2048 個細讀
- **Engram（條件記憶）**："多少 token 不需要被理解？"——查表替代深層重建（業界有層深度路由 MoD 思路，DeepMind 2024；DeepSeek 官方路線是 DSA + Engram，不用 MoD【素材 04 §0.1】——這句作口播備料，頁面不展開）
- 一句話：**智慧不需要全部參數、也不需要全部深度——把算力花在最值得的 token 上**
- 頁面落點：**模型變大與變貴第一次脫鉤**（記憶數：3%）
- 觀眾 takeaway：**模型"變大"和"變貴"脫鉤了——省算的第一招不是砍模型，是讓模型自己少幹活**

### 4.4 儲存維 · 架構：上下文越來越長怎麼辦 → MLA + 量化（頁面 13，1.5 分钟）

- 承接頁面 10 的 KV 定義：KV 大小 ≈ 層數 × 頭數 × 維度 × token 數（× K/V 兩份 × 精度）——上下文 4K → 128K → 1M，KV 按長度線性增長【素材 04 §1】
- **格式壓縮 MLA（頁面主對照）**：同一 1M 上下文，標準 BF16 GQA8 要 **250GB** 顯存；DeepSeek V4-Flash（MLA 把 KV 壓進 512 維潛空間）只要 **約 5GB（≈2%）**——省 **93%**（記憶壓成摘要存檔，用的時候再展開）
- **量化（精度壓縮，頁面副數字）**：把每步要讀的激活專家權重壓成 4-bit——讀取量 **26GB → 6.5GB（÷4）**（口徑：V4-Flash 激活 13B，混合精度部署）——decode 是"讀權重"的頻寬遊戲，讀得越少跑得越快
- 頁面落點：**記憶不必完整（壓縮後仍可恢復），也不必全部看（只讀相關的）**——推理降本的本質是"省記憶"，不是"省電"
- 觀眾 takeaway：**同一個 1M 上下文，存檔從 250GB 瘦身到 5GB——"記性好"第一次不靠"倉庫大"**

### 4.5 儲存維 · 系統：顯存不夠用怎麼辦 → PagedAttention + 字首快取（頁面 14，1 分钟）

- **PagedAttention（顯存版的作業系統虛擬記憶體）**：KV 切塊、按需放格、塊表索引——顯存利用率從 20–40% 提到 **90%+**（頁面畫面：快遞櫃——裝幾格算幾格，不為最長包裹包下整面牆）
- **字首快取**：命中 **93%+** = 跳過 prefill 重算、邊際成本趨零——多輪對話、Agent 多步、系統提示詞全命中
- **小米實證（頁面落點）**：全鏈路最佳化後 API **最高降價 99%，仍維持收支平衡**——"省記憶"直接變成"敢降價"【素材 04 §1.3】；白皮書旁證：AI 質檢動態批處理降本 55%、生物製藥 PagedAttention 利用率提升 4 倍【素材 07 §四】
- 觀眾 takeaway：**2026 年"降價 99% 仍收支平衡"不是口號，是賬本事實**

### 4.6 通訊與時間維：模型拆開的代價與利用率槓桿（頁面 15，1.5 分钟）

- **壓力（頁面辦公室畫面）**：模型大到必須拆卡——MoE 的 all-to-all（每個 token 跨卡找專家）、TP 的 all-reduce、PD 分離的 KV 搬運；類比：把團隊拆到幾個辦公室（專家 / 層 / KV 各據一方），跨辦公室的每次溝通都慢且貴；**通訊成為新瓶頸**【素材 04 §0.3】
- **通訊稅（頁面底部注，模型越大稅率越高）**：單節點 NVLink（≈HBM 頻寬的 1/9）通訊大部分可隱藏、接近理論；跨節點 IB（≈1/160）完全無法隱藏、產能拖死（AWS 實測 30×）【素材 11】——**拓撲是產能數字的一部分**
- **對策**：專家本地化（把專家放在常來的 token 旁邊）、PD 分離（讀題吃算力、生成吃頻寬，KV 從 prefill 池搬到 decode 池）、拓撲感知排程——騰訊太極 16×H20 實測 **15,800 tok/s**，端到端 **+30–40%**
- **時間維（運營，頁面右注）**：連續批處理把利用率 30% → 70–80%——同樣的三維消耗下產出翻倍；補上因果鏈：**延遲要求越苛刻 → batch 越小 → 利用率越低 → 單位成本越高**——把"延遲約束"接到第二部分"利用率是命脈之一"上
- 頁面落點：**通訊是三維中最難稀疏化的一維——這也是"技術派"玩家的生存空間**
- 觀眾 takeaway：**同樣的卡，排程與拓撲不同，產出差幾倍**

### 4.7 能量的角色：三維共同的物理地板（頁面 16，1.5 分钟）

- 計算/儲存/通信都能"少做"，但供電是物理硬約束：頁面標題即論點——**1GW 的工廠永遠不會變成 2GW：只有提升 Tokens/Watt 一條路**；黃仁勳的原話是"值錢的不是算力，是**'每度電的智商'**"【素材 02 §5】
- 頁面左注兩句：功率是物理上限；**折舊可攤薄、電力攤不薄**（回扣第二部分口徑之爭——資本成本與電力成本同源，都由"每瓦 token 產出"決定）
- 硬體代際 = 物理地板的抬升（頁面數字）：同一 1GW 資料中心兩年 token 生成速率 **350×**（廠商口徑）vs 摩爾定律同期 **1.5×**；GB300/Blackwell 每瓦 token 比 Hopper 高 **35–50 倍**；Vera Rubin 官方口徑：成本降至 Blackwell 的 **1/10**【素材 04 §0.4】
- 誠實宣告（頁面腳註原文，把誠實轉化為論證資產）：**350× 為英偉達口徑，SemiAnalysis 獨立實測約 50×——方向一致；即便打一折，也快過摩爾定律同期 20 倍**
- 趨勢印證（口播一句）：白皮書四大趨勢之首是"算電深度繫結"——工廠選址優先風光/核電資源、自建微電網離網供電【素材 07 §六】
- 觀眾 takeaway：**三維稀疏化 × 每瓦產出——技術革命是乘法不是加法**（記憶數：350× 記得帶"廠商口徑"）

### 4.8 價格瀑布：技術革命在賬本上的結果（頁面 17，1.5 分钟）

- 時間線（頁面四個錨點）：GPT-4（$60 輸出，2023-03）→ GPT-4o mini（$0.6，2024-07）→ DeepSeek R1（$2.19，2025-01）→ Qwen3.8-Flash（$0.43，2026-08）——單價跌 **140 倍**；而模型變聰明、token 用得少，真實任務花費降得更多（頁面右注）
- **輸出/輸入價差（頁面標題級事實）**：輸入可並行、輸出序列自迴歸——GPT-3.5 時代價差 1:1，GPT-5 已達 **1:8**——技術革命不只降價，還改寫了價格結構（回扣開場：報的都是輸出價）

- 點題：第二部分問"價格這麼低為什麼還有人建"，第三部分給答案：**不是市場瘋了，是成本真的被革命了**——革命後的單位成本已低於市場價（成本是一個區間，技術革命把整個區間往下壓）

### 4.9 市場旁證：價格還在跌（頁面 18，1 分钟）

## 六、第四部分：革命之後發生什麼（8 分钟，4 頁：19–22）

**目標**：給出全篇的"反直覺高潮"（價格跌、盤子漲），把競爭主線從"更便宜"翻轉到"更值錢"，落到頁 22 的兩條路。

### 5.1 傑文斯悖論：為什麼價格跌、用量反而暴漲（頁面 19 提問 + 頁面 20 揭曉，2.5 分钟）

- 經濟學經典（150 年前的預言）：煤便宜了，用量多了，總開支反而漲【素材 05 §1】
- **互動設計（頁面 19 無標題、只有大字，全篇最大懸念）**："單價跌了 140 倍——你們猜，這個行業的**總盤子**是漲了還是跌了？"停頓 3–5 秒，環視全場，再翻頁給資料（問題與資料對齊：用量 ×14 / Google ×134 / 中國 ×1400）
- **AI 實錘資料（頁面 20 三卡）**【素材 05 §1.3】：
  - OpenAI Luna 降價 80% → 兩週呼叫量 **×14**、收入 **+34%**（TD Cowen / OpenRouter 資料）
  - Google 月 token 處理量：9.7 萬億 → 1300 萬億（約 **134 倍**）
  - 中國日均：1000 億 → 140 萬億（兩年約 **1400 倍**）
  - （備用資料，口播可略：Terra 降價 20% → 用量 ×5、收入 +45%；IDC 五年 3 億倍口徑互斥見素材 05；微軟 Q1 FY2026 處理超 100 萬億 token、同比 5 倍）
- **機制（頁面 20 下半區）：消耗主體從"人"變"機器"——Agent**：幹一件事呼叫模型 **10–20 次**、token 耗用是普通對話的 **5–30×**（Gartner）；J 型爆发：**2026–2028 大規模部署關鍵拐點**（HF Hub agent 流量實測備料：2026 年 4 月 Claude Code 一家占 67.8%，7 月降至 44.4%、Codex 升至 20.8%——份額此消彼長不是 Agent 退潮，是十多個新客戶端湧現、生態分化【素材 08 §4】）
- **飛輪迴扣（20 秒）**："還記得第二部分 07 頁的命脈兩數嗎？① 吞吐利用率靠技術革命撬動（第三部分），② 需求靠降價撬動（剛才這些數字）——技術降本 → 降價 → 需求漲 → 時間佔用率升 → 再降本。它正在轉。"
- 深刻點（頁面底注原句）：**真正可怕的訊號不是"單 token 價格歸零"，而是"價格跌但用量停滯"——目前沒發生**
- 觀眾 takeaway：**成本革命的最大受益者不是消費者，是整個產業盤子**

### 5.2 競爭維度的遷移：從"誰的 GPU 多"到"誰的 token 值錢"（頁面 21，1.5 分钟）

- 第一層：**效率競爭**——比每瓦 token（成本端）：固定功率下，每瓦產出越高，成本越低；黃仁勳"1GW 工廠 15 年攤銷 400 億美元，必須放最強機器"【素材 02 §2】
- 第二層：**價值分層**——token 分層定價（頁面價格階梯：$0 免費客戶 / $3–6 普通使用者 / $45 深度推理使用者 / $150 關鍵場景使用者）【素材 02 §2】
- 第三層：**生態卡位**——聚合平台、Token 運營商（中國電信 9.9 元套餐、算力網入"六張網"、首個百億級 Token 工廠集採 164 億【素材 05 §4】）、行業方案——類比：電力產業最終不是賣電賺錢，是賣電器、電網、電網服務
- 頁面落點條：**價值正在從 token 本身，上移到 Agent、工作流與行業方案**——競爭的主戰場換了
- 觀眾 takeaway：**競爭的勝負手從"算力"轉移到"效率 × 生態"**

### 5.3 機會：讓 token 更值錢（頁面 22，2 分钟——全篇落點頁）

- **頁面標題即論點**：機會不在更便宜的 token，在更值錢的 token（回扣開場三問之②"怎麼才能賺錢"）
- **對照卡（同一家公司、同一個 2026，兩種賣法）**：
  - 賣"便宜的 token"（通用 token 走量）：矽基流動 · 公有云服務毛利率 **−119%**——代金券補貼換增長，賣 1 元虧 1.19 元——**價格戰裡沒有贏家**
  - 賣"值錢的 token"（行業 Know-how 封裝）：矽基流動 · 本地部署行業方案毛利率 **+82.5%**——金融/能源/政務客戶為方案付費——**同樣的卡，賣法不同**
  - 講解口徑：這不是兩家公司，是同一家公司內部的兩條產品線——**證明"值錢"不是運氣，是選擇**
- **兩條路卡（頁面底部，本頁第二個觀點）——讓 token 更值錢的兩條路**：
  1. **生產垂類 token**：把行業 Know-how 封裝進 token 與方案——賣溢價，不卷價格（回扣 05 頁模式尺的"垂類 Token"）
  2. **在應用層消耗**：Agent、工作流、行業方案——價值在結果，不在 token 本身（回扣 20 頁的 Agent 驅動）
- **冷靜註腳（口播，防"那就都去做垂類"的誤讀）**：兩條路都吃"效率底座"——頁 22 之前的三維稀疏化與每瓦產出，是你能在這兩條路上活下來的前提；重資產玩家也別急著退場——輕資產路徑（不買卡只租卡、聚合平台）與長週期玩家（政府/電信集採攤薄折舊）同樣成立【素材 03 §4】
- 觀眾 takeaway：**怎麼賺錢？不是把 token 賣得更便宜，是把同樣的卡，賣到更值錢的場景裡**
